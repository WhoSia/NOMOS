# NOMOS Routing Learning 0.1

This format describes **revision of a routing policy using outcomes generated under prior routing policies**.

It audits the learning process. It does not infer whether a person is risky, blameworthy, truthful, competent, or deserving of a consequence.

## Core problem

Suppose a correction signal such as reversal or remand is observable mainly after a case enters a deep review route.

Then the number of observed corrections in epoch t is approximately:

```
observed corrections
≈ case volume × deep-review exposure × correction rate conditional on deep review
```

A decline in raw correction count can therefore be produced by a decline in review exposure even when the correction rate among reviewed cases does not improve.

Routing policy can thus manufacture the data later used to evaluate itself.

## Feedback declaration

```json
{
  "feedback": {
    "correction_signal": "correction_outcome",
    "observable_on_routes": ["deep_review"],
    "unobserved_outside_routes": true
  }
}
```

This records where the claimed learning signal is actually observable.

## Epochs

Each epoch records:
- policy version;
- case volume;
- load;
- route exposure;
- observed corrections;
- revision signals;
- revision rule version/provenance.

The analyzer reports both raw correction counts and exposure-normalized correction rates.

## Policy revision classes

### Outcome-blind operational revision
Uses signals such as:
- load;
- queue delay;
- staff capacity;
- case volume;
- pre-outcome case features.

This can justify operational adaptation within its declared scope.

It does **not** by itself establish that the prior epistemic routing rule was accurate.

### On-policy epistemic revision
Uses reversal, remand, correction rate, or related review outcomes generated under the routing policy itself.

This requires an identifiability audit because outcome observability may be route-selected.

## Independent learning channels

The specification supports:
- `independent_audit`;
- `shadow_review`;
- `natural_overlap`;
- `off_policy_evaluation`;
- `frozen_holdout`.

These are not interchangeable and are not automatically sufficient.

They record that the system has at least one learning route not wholly generated by the policy being evaluated.

## Safety / authority rule

NOMOS does not require harmful or entitlement-denying experimentation.

If learning would require deliberately withholding a review path that a case is already entitled to receive, set:

```json
{
  "exploration_requires_withholding_entitled_review": true
}
```

The analyzer returns `REVISION_METHOD_REJECTED`.

Preferred evidence sources include:
- naturally occurring overlap;
- independent audit;
- non-consequential shadow review;
- historical policy variation with adequate provenance;
- randomization only among routes already acceptable for the case.

## Findings

- `SELECTIVE_ROUTING_FEEDBACK`
- `RAW_COUNT_SELF_CONFIRMATION`
- `LOAD_CORRECTION_CONFOUNDING`
- `REVISION_PROVENANCE_GAP`
- `ON_POLICY_SELF_EVALUATION_GAP`
- `OUTCOME_CONDITIONED_REVISION_RULE`
- `UNSAFE_EXPLORATION_PROPOSAL`

## States

- `REVISION_METHOD_REJECTED`
- `REVISION_GOVERNANCE_HOLD`
- `REVISION_IDENTIFIABILITY_HOLD`
- `REVISION_IDENTIFIABILITY_CANDIDATE`

`REVISION_IDENTIFIABILITY_CANDIDATE` is not a policy endorsement. It means the submitted structure does not exhibit the specific blocking defects encoded by this research kernel.
